# 产品需求说明

## 1. 项目背景

企业员工遇到账号、网络、软件、设备和数据问题时，如果主要依赖口头沟通或即时消息，容易出现问题遗漏、责任人不清、处理进度不可追踪和高频问题无法复盘等情况。

本项目设计一个轻量IT工单系统，将问题提交、分配、处理、解决和关闭过程结构化，并通过运营看板帮助管理者发现超时工单和高频问题。

## 2. 项目目标

- 为员工提供统一的问题提交入口。
- 为技术人员提供待办列表和状态流转能力。
- 保留负责人、解决方案和操作时间线。
- 自动计算不同优先级的SLA期限。
- 为管理者提供效率和问题结构看板。

## 3. 用户角色

| 角色 | 主要任务 |
|---|---|
| 提交人 | 创建工单、描述问题、查看结果 |
| 技术人员 | 接收工单、处理问题、填写解决方案 |
| 管理员 | 分配负责人、查看全部工单和运营看板 |

当前演示版本通过预置用户模拟操作人，不包含真实登录认证。

## 4. 核心流程

```mermaid
flowchart LR
    A[员工提交工单] --> B[管理员受理]
    B --> C[分配技术人员]
    C --> D[开始处理]
    D --> E[填写解决方案]
    E --> F[关闭工单]
    E -->|问题未解决| D
```

## 5. 功能需求

### 5.1 创建工单

必填字段：标题、问题描述、提交部门、问题类型、优先级和提交人。

系统根据优先级生成SLA时间：

| 优先级 | SLA |
|---|---:|
| 低 | 72小时 |
| 中 | 48小时 |
| 高 | 24小时 |
| 紧急 | 8小时 |

### 5.2 工单列表

- 支持分页。
- 支持按编号、标题和描述搜索。
- 支持状态、优先级、部门和问题类型筛选。
- 显示负责人及创建时间。

### 5.3 工单处理

- 新建工单必须先分配负责人。
- 已分配工单可以进入处理中。
- 处理中工单填写解决方案后可以标记为已解决。
- 已解决工单可以关闭，也可以重新打开。
- 已关闭工单可以因复发而重新进入处理中。

### 5.4 操作日志

记录创建、信息更新和状态变更，包括操作人、时间、原状态、新状态和备注。

### 5.5 运营看板

- 工单总数
- 已解决及已关闭数量
- 解决率
- 平均处理时长
- 超时未完成数量
- 状态、优先级、问题类型和部门分布
- 近30天新增及已解决趋势

## 6. 非功能需求

- 中文界面清晰可读。
- 接口错误返回明确的信息。
- 数据库启用外键约束。
- 列表在220条模拟数据下保持流畅。
- 核心业务规则需要自动化测试。

## 7. 验收标准

1. 可以创建一条包含所有必填字段的工单。
2. 新工单默认状态为待受理，并自动生成编号和SLA时间。
3. 工单无法跳过中间步骤直接关闭。
4. 解决工单时未填写解决方案会被拦截。
5. 列表筛选结果与条件一致。
6. 看板总数与数据库工单数量一致。
7. 操作时间线能够显示状态变更记录。
