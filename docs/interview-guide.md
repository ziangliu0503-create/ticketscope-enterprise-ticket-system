# 面试讲解与问答

## 30 秒介绍

我独立完成了一个企业 IT 工单与 SLA 运营系统。项目采用 Vue、Flask 和 SQLite，覆盖三角色登录鉴权、工单状态流转、SLA 预警与升级、操作日志、运营看板和 Excel 导出。我还把权限、非法流转和报表导出写成自动化测试，并补充了 Docker 和云部署配置。项目数据均为模拟数据，重点是展示我把业务流程转化为系统规则并完成验证的能力。

## 一分钟介绍

我想申请数字化实施、IT 支持和需求分析类岗位，所以选择企业内部报障场景做了 TicketScope。首先我把普通员工、技术人员和管理员的职责整理成角色权限矩阵，再把工单流程设计为受控状态机。后端使用 Flask 提供 REST API，SQLite 保存用户、工单和操作日志，前端使用 Vue 与 ECharts 实现处理页面和运营看板。系统会按优先级计算 SLA，区分正常、临期、超时、达标和违约，管理员还可以对超时工单执行 L1 到 L3 升级。最后我用 Pytest 覆盖登录、数据隔离、非法流转、看板和 CSV/Excel 导出，并用 Gunicorn 做生产模式验证。

## 三分钟讲解结构

1. **问题**：群聊报障容易遗漏、责任不清、时限不可量化。
2. **需求**：三角色、五状态、SLA、日志、看板、导出。
3. **设计**：前后端分离，后端统一执行权限和状态规则，日志追加保存。
4. **实现**：Vue + Flask + SQLite；签名令牌、ECharts、openpyxl、Pytest。
5. **验证**：8 个自动化测试、生产构建和 Gunicorn 冒烟测试通过。
6. **复盘**：演示版选择 SQLite 降低运行门槛；真实部署将改 PostgreSQL 和 SSO。

## 高频问题

### 为什么权限不能只在前端控制？

前端隐藏按钮只能改善体验，用户仍可能直接调用接口。所以后端每次请求都会验证令牌、角色、数据范围和允许的状态变化，前端只是根据后端返回的权限渲染页面。

### RBAC 怎么实现？

用户表保存 `requester`、`agent`、`admin` 三种角色。鉴权装饰器校验签名令牌，查询层按角色拼接数据范围，详情接口返回允许的操作；写接口再次校验角色和工单归属。

### SLA 是如何计算的？

创建时根据优先级生成 `due_at`：低 72 小时、中 48 小时、高 24 小时、紧急 8 小时。未完成工单进入最后 25% 时限显示临期，超过截止时间显示超时；已完成工单用 `resolved_at` 与 `due_at` 判断达标或违约。

### 为什么设计操作日志表？

工单表只表达当前状态，不能说明过程。日志表以追加方式保存操作人、时间、原状态、新状态和备注，可以用于审计、复盘和定位异常。

### 为什么使用 SQLite？

这是校招演示项目，SQLite 能让面试官在不安装数据库的情况下快速运行。它不是我对生产数据库的最终选择；生产环境会用 PostgreSQL/MySQL、迁移工具和连接池。

### 导出如何保证与页面一致？

列表和导出共用同一个筛选构建函数与角色数据范围。CSV 使用 UTF-8 BOM 方便 Excel 打开中文，XLSX 使用 openpyxl 设置表头、列宽和冻结行。

### 遇到的主要难点是什么？

一是避免不同角色绕过页面操作不属于自己的工单，因此把数据范围和状态权限都放到后端。二是 SLA 不只是“是否超时”，还要区分未完成和已完成，所以分别用当前时间或解决时间与截止时间比较。三是看板、列表和导出必须口径一致，因此复用筛选逻辑并用测试核对汇总。

### 如何测试？

我使用临时 SQLite 数据库运行 Pytest，覆盖公开健康检查、登录、三角色数据隔离、普通员工创建、管理员完整流程、非法跳转、SLA 筛选、看板合计和 CSV/Excel 导出。前端还执行 Vite 生产构建，并用 Gunicorn 做关键接口冒烟测试。

### 如果再迭代，你会做什么？

优先增加企业 SSO、PostgreSQL、附件对象存储、邮件/企微通知和定时 SLA 升级；之后补充接口文档自动生成、审计字段、监控告警和部署流水线。

## 演示顺序

1. 普通员工登录并创建高优先级工单。
2. 管理员登录，在待受理列表中分派负责人。
3. 技术人员登录，推进至处理中并填写解决方案。
4. 展示操作时间线、SLA 标签和角色可见范围。
5. 管理员展示看板、SLA 筛选及 Excel 导出。

## 诚实边界

- 可以说“独立设计并实现”“使用模拟数据完成验收”。
- 不要说“在某公司生产上线”“服务真实用户”“提升效率 30%”，除非确有证据。
- 还没有掌握的技术可以说“了解改造方案并能说明选型”，不要表述为熟练生产实践。
